# Strata on an NVIDIA GB10 (DGX Spark), arm64 CUDA build — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Strata's installer see an NVIDIA GB10 on Linux/arm64, compile the CUDA engine here for `sm_121`, and run IQ3_S on it.

**Architecture:** The Metal port is the template. The CUDA side stays whole; the CPU kernel library is reduced to the three files Metal builds, with a five-line `immintrin.h` for the two intrinsics the engine's host side uses, and the AVX expert kernels replaced by entry points that say plainly that this build has no CPU expert kernels. The GPU does the model's math; the CPU keeps only the router's plain-C++ estimate, the expert blob layout and the thread pool.

**Tech Stack:** C++17 + CUDA 13 (nvcc 13.0.88, `sm_121`), CMake 3.28, Python 3.12 (`setup.py`, `tools/test_setup_*.py` with `unittest`), ggml from a pinned llama.cpp checkout.

**Spec:** `docs/superpowers/specs/2026-10-17-spark-arm64-cuda-design.md`

## Global Constraints

- The x86 path stays byte-identical: same files, same flags, same engine, same messages. Only an arm64 host takes the new code, and it takes it by the host processor, not by a new option.
- Every backend a touched file builds is built or configured before review: CUDA, HIP, SYCL, and Metal for anything under `metal/`. On this NVIDIA-only box HIP and SYCL mean *configure*, not run.
- Docs keep plain words, measured numbers, and what each number was measured on; no claim without a run.
- Target model: **IQ3_S** (83.6 GB download, 62 GB RAM, 50.3 GB arena — `setup.py:252-253`). CUDA arch `121` from `nvidia-smi`'s compute capability `12.1`.
- The unified-memory headroom is the constant the engine already uses: `UMA_OS_LEFT_GB = 6` (`setup.py:2245`), the same 6 GiB `device_free_bytes()` leaves.
- Never expose the server beyond `127.0.0.1` without `--api-key`.
- Setup's own tests must keep running with no GPU and no download: `python3 -m unittest tools.test_setup_spark`.

## Review Focus

- A **discrete** card whose `memory.total` is not a number (a driver quirk, a vGPU, MIG) must not be handed the whole system RAM as if it were unified — the fallback needs a second signal, not just a missing figure. → Task 2, `test_a_card_that_reports_no_memory_but_is_not_integrated_is_not_given_the_ram`.
- An **x86 CPU whose `/proc/cpuinfo` has no `flags:` line** (a VM, a patched cpuinfo) must not be promised an AVX-512 build: setup says it could not read the CPU's flags and builds the no-floor engine. → Task 1, `test_an_x86_cpu_without_a_flags_line_says_the_flags_could_not_be_read`.
- An arm64 user who asks for the CPU prefill share gets a plain sentence saying this build has no CPU expert kernels, not a stop that names an entry point. → Task 6, `test_asking_for_the_cpu_share_on_arm64_says_so`.
- A pack that insists on CPU expert support stops with `cpu_require_expert_support()`'s words, never an undefined symbol. → Task 5, the link step and the run in Task 7.
- A unified card's shared memory must not be counted as room beside the RAM in the low-RAM mode — the rule `low_ram_vram()` already makes for an AMD APU. → Task 2, `test_a_unified_card_adds_nothing_beside_the_ram_in_low_ram_mode`.

def test_a_unified_card_is_measured_from_the_ram_it_can_reach(self):
